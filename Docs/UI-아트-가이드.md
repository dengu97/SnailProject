# UI 아트 가이드

UI.pptx 목업에서 실제 치수를 뽑아 정리한 것. 새 UI 아트를 그릴 때 이 문서만 보면 된다.

---

## 1. 기준: 목업 1pt = 화면 1px

UI.pptx 슬라이드1(예상 사이즈)에서 계산한 값이다. 바탕화면 스크린샷이 3835px 폭인데
슬라이드 안에서 780pt를 차지하고, UI 그룹이 148.4pt다. 환산하면 UI가 화면에서 730px.
목업 자체 치수(패널 173pt)와 비교하면 **1pt ≈ 1080p 화면의 1px**.

> 즉 **파워포인트에서 잰 숫자를 그대로 픽셀로 쓰면 된다.** 코드도 그렇게 되어 있다
> (`UiTheme.At`). 목업 치수를 바꾸면 코드 상수도 그 숫자로 바꾸면 끝.

---

## 2. 둥근 사각형 — 지금은 코드 생성, 아트로 갈아끼울 수 있다

코드가 만드는 도형은 **자리를 채워 두는 것**이지 최종본이 아니다. 아트를 넣으면 그쪽이 이긴다.
`Resources/Ui/Shape/` 에 아래 이름으로 넣기만 하면 되고, **배치 코드는 한 줄도 안 바뀐다.**

| 파일 이름 | 쓰이는 곳 | 화면에서 가장 작게 쓰이는 크기 |
|---|---|---|
| `panel.png` | 큰 판 (디폴트·목록·상세) | 173 × 220 |
| `panelborder.png` | 판의 테두리 | 173 × 220 |
| `slot.png` | 이름칸 · 게이지 트랙 · 목록 행 · 음식 슬롯 | 32 × 12 |
| `badge.png` | 등급 · 나이 · 코인 알약 | 35 × 12 |
| `fill.png` | 게이지 채우기 | 10 × 8 |
| `button.png` | 버튼 배경 (설정 등) | 24 × 22 |

**여섯 개면 끝난다.** 위젯마다 그리는 게 아니라, 같은 조각이 여러 크기로 늘어나 쓰인다.
그래서 9-슬라이스 규칙(8번)을 지켜야 한다.

판과 테두리가 나뉜 이유: 채우기색과 테두리색을 따로 물들여야 해서다. 테두리까지 그린
`panel.png` 하나로 하고 싶으면 `panelborder.png` 를 빼고 알려주세요 — 코드에서 빼겠습니다.

색을 아트에 넣으면 `UiTheme` 의 색 상수를 흰색으로 바꿔야 원본 색이 나온다. 알려주시면 맞추겠습니다.

> 지금 화면에 보이는 도형이 아트인지 코드 생성인지는 실행 리포트(`unity-probe-result.txt`)의
> `도형:` 줄에 나온다. `Panel=아트, Slot=생성` 처럼 조각별로 찍힌다.

## 3. 그려야 하는 것

전부 **아이콘**이다. 화면 크기는 목업에서 잰 값.

| 쓰임 | 화면 크기 | 파일 이름 | 상태 |
|---|---|---|---|
| 탭 4개 (달팽이·음식·알·상점) | 28 × 24 | `icon_snail` `icon_food` `icon_egg` `icon_shop` | 있음 |
| 설정 | 28 × 24 | `icon_settings` | 있음 |
| 코인 | 22 × 22 | `icon_coin` | 있음 |
| 닫기 · 최대화 | 28 × 28 | `btn_close` `btn_maximize` | 있음 |
| 이름 수정 (연필) | 16 × 16 | `icon_rename` | 있음 |
| 게이지 (잎·하트) | 19 × 18 | `icon_food` `icon_happy` | 있음 |
| 하단 액션 4개 | 24 × 22 | `icon_detail` `icon_wardrobe` `icon_gene` `icon_sell` | 있음 |
| 목록 교체 | 22 × 22 | `icon_swap` | 있음 |
| 즐겨찾기 | 16 × 16 | `icon_favorite` | 있음 |
| 달팽이 썸네일 | 32 × 32 | (런타임 합성) | 그릴 필요 없음 |
| 음식 슬롯 아이콘 | 32 × 32 | 음식별 아트 | **필요** |

## 4. 작업 캔버스: **256 × 256 정사각형**

화면에서는 16~32px로 나오지만 크게 그려서 줄인다. 이유는 두 가지다.
고해상도 화면에서 UI를 키울 여지를 남기고, 줄이는 것은 공짜지만 늘리면 뭉개진다.

- **캔버스 256×256 고정.** 아이콘마다 다르게 하면 화면에서 크기가 들쭉날쭉해진다
- **내용은 캔버스의 약 85%**, 가운데 정렬. 가장자리 여백이 곧 아이콘 사이 간격이 된다
- **배경 투명.** 흰 배경으로 저장하면 흰 사각형이 그대로 보인다
- 가로세로 비율이 다른 아이콘도 정사각 캔버스에 넣는다. 코드가 비율을 유지해 맞춘다
  (`preserveAspect`)

임포터가 256으로 잘라내므로 512로 그려도 되지만 파일만 커진다.

## 5. 색 규칙

두 종류가 있고, 코드가 다르게 다룬다.

**실루엣 아이콘** — 단색(검정)으로 그린다. 코드가 런타임에 물들인다.
지금 대부분이 이쪽이다. 나중에 비활성/강조 상태를 색으로 표현할 수 있다.

**색이 들어 있는 아트** — 그린 색 그대로 나온다. `btn_close`, `btn_maximize`, `icon_coin`.
이런 건 코드에서 흰색으로 넘겨 원본 색을 유지한다.

새 아이콘이 어느 쪽인지 알려주시면 코드에서 맞추겠습니다. 헷갈리면 **실루엣이 안전**하다.

## 6. 내보내기 · 이름 · 위치

```
저장 위치 : SnailPet/Assets/Resources/Ui/Icon/
형식      : PNG (알파 포함, 32비트)
이름      : icon_기능이름.png   (영문 소문자 + 밑줄)
```

이름은 **기능**으로 짓는다. `icon_leaf` 가 아니라 `icon_food`. 나중에 잎이 다른 그림으로
바뀌어도 이름을 안 바꿔도 된다.

폴더에 넣기만 하면 임포트 설정은 자동으로 잡힌다 (`SnailArtImporter`).
`Resources/Ui` 밖에 두면 안 된다 — 달팽이 파츠 규칙(1픽셀=1월드유닛)이 걸려서 UI가 깨진다.

## 7. 파워포인트에서 뽑을 때 함정

도형 우클릭 → **그림으로 저장** 은 **화면에 보이는 크기 그대로** 내보낸다.
28pt 짜리 도형이면 41×41px 로 나온다. 실제로 `btn_close` 가 그렇게 들어왔다.

지금 크기로도 1:1 로는 보이지만 여유가 없다. 크게 뽑으려면:

1. 슬라이드에서 도형을 **크게 키운 뒤** 저장하고 원상복구, 또는
2. 도형 복사 → 새 그림판/포토샵에 붙여넣기 → 256으로 리샘플

급하지 않다. 나중에 다시 그릴 때 256으로 맞추면 된다.

## 8. 둥근 사각형 그리는 법 (9-슬라이스)

### 캔버스: 화면 크기의 **4배**

9-슬라이스의 모서리는 **원본 픽셀 크기 그대로** 찍힌다. 1:1 로 그리면 모서리가 6px밖에
안 돼 디자인을 넣을 자리가 없다. 그래서 4배로 그린다. 임포터가 PPU를 4로 잡아서
화면 크기는 그대로 유지된다 (`SnailArtImporter.ShapeScale`).

| 파일 | 캔버스 | 모서리(슬라이스 여백) | 화면에서의 모서리 |
|---|---|---|---|
| `panel` · `panelborder` | 96 × 96 | 32 | 8px |
| `slot` · `badge` · `button` | 64 × 64 | 24 | 6px |
| `fill` | 48 × 48 | 20 | 5px |

**모서리는 화면에서 쓰이는 가장 작은 크기의 절반을 넘으면 안 된다.**
게이지 트랙이 12px 높이니 모서리는 6px까지다. 그보다 크면 위아래 모서리가 겹쳐 뭉개진다.

### 어디가 늘어나는가

```
┌───┬───────┬───┐   모서리 4칸 : 원본 크기 그대로. 무늬·굴곡 자유
│ ◜ │   ↔   │ ◝ │   위·아래 변 : 가로로만 늘어남 → 세로 그라데이션 OK, 가로 무늬 X
├───┼───────┼───┤   좌·우 변   : 세로로만 늘어남 → 가로 그라데이션 OK, 세로 무늬 X
│ ↕ │   ↔↕  │ ↕ │   가운데     : 양방향으로 늘어남 → 단색만
├───┼───────┼───┤
│ ◟ │   ↔   │ ◞ │
└───┴───────┴───┘
```

**주의할 것 하나**: 판 전체에 세로 그라데이션을 넣으면 안 된다. 가운데 칸이 세로로도
늘어나서 그라데이션이 뭉개진다. 세로 그라데이션이 꼭 필요하면 알려주세요 —
가로로만 늘어나는 방식(3-슬라이스)으로 바꾸면 된다.

그림자·광택도 같은 이유로 조심해야 한다. 모서리 안에 들어가는 건 괜찮고,
판 전체에 걸치는 것은 늘어나면서 어색해진다.

### 넣는 법

1. PNG(알파)로 `SnailPet/Assets/Resources/Ui/Shape/` 에 저장
2. 유니티에서 그 파일 선택 → 인스펙터 **Sprite Editor** → 사방 여백을 위 표대로 설정
3. 끝. 실행하면 자동으로 그쪽이 쓰인다

2번이 번거로우면 그냥 넣어만 주세요. 여백 값을 알려주시면 제가 잡겠습니다.

## 9. 글꼴

`SnailPet/Assets/Resources/Ui/Font/` 에 `.ttf` 또는 `.otf` 를 **하나** 넣으면
UI 글자 전체가 그것으로 바뀝니다. 파일 이름은 상관없고, 코드를 고치거나
프리팹을 다시 구울 필요도 없습니다.

비어 있으면 OS 글꼴(맑은 고딕)로 떨어집니다.

- **한글 글리프가 있어야** 합니다. 영문 전용이면 한글이 네모가 됩니다
- **재배포·임베딩이 허용된 라이선스**여야 합니다. 빌드에 글꼴 파일이 그대로 들어갑니다
- 화면에 **8~12px** 로 나오므로 작은 크기에서 읽히는지 보고 고르세요.
  획이 얇거나 장식이 많으면 뭉갭니다
- 두 벌 이상 두지 마세요. 처음 찾은 것을 쓰고 경고가 남습니다

레거시 `Text` 는 TTF 를 그때그때 렌더하므로 한글 아틀라스를 미리 구울 필요가
없습니다. TMP 였다면 글꼴을 바꿀 때마다 2,350자 이상을 다시 구워야 합니다.
