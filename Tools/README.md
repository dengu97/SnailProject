# 파츠 합성 프리뷰 툴

SnailData.xlsx + `SnailPet/Assets/Resources/Snail/` 를 그대로 읽어서 달팽이 조합 결과를 눈으로 확인하고,
부화·교배 추첨 로직과 데이터 정합성을 Unity 붙이기 전에 검증하는 도구입니다.

## 사용법

1. **데이터 갱신** — `SnailData.xlsx` 를 수정한 뒤 아래를 실행합니다. (Excel 이 켜져 있어도 됩니다.)

```bash
powershell -ExecutionPolicy Bypass -File Tools/ExportSnailData.ps1
```

2. **열기** — `Tools/preview/index.html` 을 브라우저로 엽니다. 서버 불필요, `file://` 로 동작합니다.

## 탭 구성

| 탭 | 하는 일 |
|---|---|
| **조합기** | 파츠·색상·악세서리를 직접 골라 합성 결과 확인. 레이어 순서를 바꿔가며 z-order 검증 |
| **부화 시뮬** | EggData 기준으로 N마리 부화. 카드를 클릭하면 그 조합이 조합기로 넘어감 |
| **교배 시뮬** | 알 2개로 부모를 만들어 자식을 뽑음. 돌연변이 실측치를 이론값과 대조 |
| **확률 분포** | 대량 추첨(기본 2만회) 후 파츠별 실제 출현 빈도 집계 |
| **도감** | SnailGuide 의 목표 조합을 그리고, 어느 알에서 나올 수 있는지·보상이 뭔지 표시 |
| **파츠 아틀라스** | PartsData·AccessoriesData 전 행을 단독 렌더링. 리소스/색상 매핑 오류가 즉시 보임 |
| **데이터 검증** | 리소스 누락, Id 충돌, 언어 키 참조, 그룹 완결성, 보상·상점 참조 점검 |

## 리소스 규약 (툴이 전제하는 것)

- 모든 파츠 PNG 는 **1200×1200 공유 캔버스**에 미리 배치 → 오프셋 없이 순수 z-스택 합성
- 선화 레이어: `SnailPet/Assets/Resources/Snail/{PartsType}/{ResourceKey}.png`
- 색상 레이어: `SnailPet/Assets/Resources/Snail/{PartsType}/Color/{ColorResourceKey}.png`
- 악세서리는 타입이 아니라 `Accessories/` 한 폴더를 씁니다 (런타임 `SnailComposer` 와 같음)
- 파츠 1개 = **색상 레이어(아래) + 선화 레이어(위)** 2장
- **색상 레이어는 선화 전용입니다.** `commonshell01_c*` 는 `commonshell01` 에만 맞고,
  `commonshell02` 에 씌우면 실루엣이 달라 색이 윤곽 밖으로 삐져나옵니다.
  조합기의 `타입 내 모든 색상 허용` 체크박스를 켜면 이 현상을 직접 확인할 수 있습니다.

**`PartsColorData` 시트는 없어졌습니다.** 색 목록의 원본은 이제 `Color/` 폴더에 실제로 있는
파일이고, 어느 선화에 맞는 색인지는 `PartsData.Colors` 열이 정합니다. 툴은 두 쪽을 합쳐
보여 주면서 한쪽에만 있는 것을 검증에서 잡습니다.

색 이름이 꼭 `{선화이름}_c##` 일 필요는 없습니다 — `commonbody05` 선화에 `tomatobody` 색을
씌우는 식으로 실루엣을 재활용하는 것이 정상입니다. 검증은 **접두사가 다른 파츠의 선화 이름과
같을 때만** 경고합니다(그때는 진짜로 남의 색을 물고 있는 것입니다).

### 애니메이션 시트

가로가 세로의 정수배인 PNG 는 **가로÷세로 칸짜리 시트**로 봅니다. 데이터에 칸 수를 적지
않으므로 3칸에서 5칸으로 바꿔도 시트를 안 고쳐도 됩니다 (런타임 `SnailComposer.FramesOf` 와 같은 규칙).
재생 속도는 **`GameConfig.AnimationSec`(다음 칸까지 몇 초)** 하나로 전부 같습니다.
`PartsData.AnimFps` 열은 남아 있지만 런타임이 보지 않으므로, 값이 적혀 있으면 검증이 경고합니다.

아틀라스 탭에서 시트 파츠에는 `애니 N칸 · X초` 뱃지가 붙습니다. 여기 뜨는 초가 이상하면
`AnimationSec` 를 고칠 때입니다.

## 이름·설명

시트는 이제 문구를 직접 들고 있지 않고 `LanguageData` 의 Id 를 가리킵니다
(`NameId` / `InfoId`). 툴은 그 Id 로 `Kr` 을 찾아 보여 주고, 못 찾으면 **토큰을 그대로**
보여 주면서 검증에서 오류로 잡습니다 — 게임에서도 똑같이 토큰이 노출되기 때문입니다.

## 레이어 순서 (z-order)

**`EnumData` 의 `SortOrder` 열**에서 읽습니다. 파츠와 악세서리가 **같은 숫자 축**을 씁니다 —
악세서리가 파츠 사이에 끼어야 하므로 배열이 아니라 숫자여야 합니다.

일부만 채워져 있으면 전체가 툴 내장 기본값으로 물러납니다
(절반만 맞는 순서로 조용히 도는 것을 막기 위함입니다).

현재 값 (뒤 → 앞):

| EnumType | EnumName | SortOrder |
|---|---|---|
| PartsType | Mucus | 50 |
| PartsType | Shell | 100 |
| PartsType | Body | 200 |
| AccessoriesType | Hat | 250 |
| AccessoriesType | Mask | 251 |
| AccessoriesType | Etc | 255 |
| AccessoriesType | Bag | 260 |
| PartsType | Feeler | 300 |
| PartsType | Eyes | 400 |

- **`EnumValue` 를 순서로 재활용하지 마세요.** EnumValue 는 직렬화 ID 라 세이브 데이터와 묶여
  있어 배포 후 변경이 불가능한 반면, 노출 순서는 아트를 보며 자주 조정하는 값입니다.
- **오름차순이 뒤 → 앞입니다.** 값이 작을수록 뒤로 갑니다.
  `Eyes` 를 `Body` 보다 작게 주면 눈이 몸통 색에 완전히 가려져 얼굴이 텅 빕니다.
  악세서리를 몸통·껍질보다 작게 주면 입은 티가 안 납니다. 검증 탭이 둘 다 오류로 잡습니다.
- 런타임은 여기에 한 단계를 더 겹칩니다 — 한 파츠 안에서 색상이 항상 선화 아래로 가도록
  `SortOrder × 2` 로 두 칸씩 벌립니다(`SnailComposer.Build`).

조합기 탭에서 순서를 바꾸면, 그 순서를 `SortOrder` 에 그대로 옮겨 적을 값이 표로 나옵니다.

## 부화 추첨 로직

1. **알의 `PartsGroupIds` 와 파츠의 `PartsGroupIds` 가 하나라도 겹치면** 그 파츠가 풀에 들어갑니다
2. 그 풀에서 `PartsType` 별로 `AppearWeight` 가중 추첨
3. 뽑힌 파츠의 `Colors` 중 1개 선택

파츠도 여러 그룹에 들 수 있습니다. **몇 개가 겹치든 풀에는 한 번만** 들어가므로 확률은
그대로입니다 (겹친 수만큼 넣으면 그 파츠만 확률이 배로 뜁니다).

그룹은 **누적 해금** 개념입니다. `[레어알01]` 은 `[일반그룹] + [레어그룹]` 을 합친
풀에서 뽑으므로, 레어그룹에 껍질만 있어도 몸·눈·더듬이는 일반그룹에서 채워집니다.
개별 그룹이 일부 파츠만 갖는 것은 정상입니다.

악세서리는 부화로 나오지 않습니다 — 입히는 것입니다.

> 기획서 「개발 명세」 에는 `1. EggData의 PartsGroupIds 중 1개 ID 무작위 선택` 이라고
> 적혀 있는데 이는 실제 사양과 다릅니다. 기획서 문구를 고쳐주세요.
> `그룹 선택` 드롭다운의 `알 그룹 1개만 무작위` 는 그 옛 문구대로 돌려보는 비교용 옵션입니다.

## 교배 추첨 로직

`SnailBreeding` 과 같은 규칙입니다.

1. 부위마다 **부모 둘의 `AppearWeight` 옆에 `GameConfig.MutationWeight` 를 한 칸 더 놓고** 추첨
2. 부모 칸에 걸리면 그 부모의 파츠를 **색까지 통째로** 물려받습니다
   (파츠와 색을 따로 뽑으면 부모 어느 쪽에도 없던 조합이 나옵니다)
3. 돌연변이 칸에 걸리면 **부모 둘의 `MutationGroup` 을 합친 것** 안에서 **같은 부위** 행을
   `MutationWeight`(비었으면 컨피그 값) 가중 추첨합니다. 뽑을 것이 없으면 없던 셈 치고
   부모 것을 물려받습니다

교배 탭의 `돌연변이율 2만회 집계` 가 실측과 이론값을 나란히 보여 줍니다.
실측이 이론보다 낮으면 그 부위의 `MutationGroup` 에 뽑을 것이 없어 부모로 되돌아간 경우입니다.

## 검증 탭이 잡는 것

- 리소스 존재 — 파츠 선화·색상, 알, 악세서리 이미지
- **언어 키** — `NameId` / `InfoId` 가 `LanguageData` 에 없으면 토큰이 그대로 노출됩니다
- **`LanguageData` 의 `Id` 중복** — 데이터 파이프라인이 여기서 멈춥니다
- `Id` 중복, 빈 `PartsGroupIds`, 빈 `MutationGroup`, 뽑히지 않는 `AppearWeight`
- 색상 파일 누락·고아, 남의 선화용 색을 물고 있는 경우
- **그룹 완결성** — 알의 풀에 빠지는 부위가 있는지
- **`SortOrder` 정합성** — 값 중복(앞뒤 비결정), 일부만 채워 폴백되는 상태,
  눈이 몸통 뒤로 가는 조합, 악세서리가 몸통·껍질에 가리는 조합
- **보상** — 개수만 있고 아이템이 없는 칸, 아이템만 있고 개수가 없는 칸, 정의되지 않은 아이템 Id
- **도감** — 참조하는 파츠·색이 실재하는지, 같은 부위가 두 번 지정됐는지,
  한 알에서 전부 뽑을 수 있는지(아니면 교배로만 도달), 보상이 비었는지
- **칸 늘리기** — `SlotSellData` 의 `PlusSlotCount` 가 1부터 끊김 없이 이어지는지,
  값이 안 적힌 칸이 있는지, `GameConfig` 의 시작 칸 수가 0이 아닌지
- **시트 간 `Id` 참조 무결성** — `ShopData` / `GachaData` / `EventData` / `SlotSellData` /
  `UnlockData` / `LevelData` 가 삭제된 아이템을 붙들고 있는지

`Food` / `Item` / `Ui` 폴더는 합성과 무관한 다른 시스템 담당이라 미사용 리소스 검사에서 뺍니다.
알의 등장 연출 시트(`{알그림}_pop`)는 데이터가 아니라 코드가 찾아 쓰므로 미사용으로 보지 않습니다.

## 이 툴과 데이터 파이프라인의 관계

같은 데이터를 보지만 역할이 다릅니다.

- **이 툴(브라우저)** — 눈으로 보는 용도. 조합 결과·부화/교배 분포·아트 매핑을 확인합니다.
- **`Tools/DataPipeline`** — 빌드 게이트. 같은 검증을 하되 **오류가 있으면 생성을 거부**합니다.

데이터를 고쳤다면 둘 다 다시 돌리세요.

```bash
dotnet run --project Tools/DataPipeline          # 검증 + 코드 생성
powershell -File Tools/ExportSnailData.ps1       # 프리뷰 툴용 data.js
```
